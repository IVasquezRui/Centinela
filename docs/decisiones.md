# Registro de decisiones — CENTINELA

Registro corto de las decisiones de arquitectura cerradas durante la planificación y por qué se descartó cada alternativa. No se reabren durante el Sprint 1 salvo acuerdo explícito del equipo completo. Contexto extendido en `../CONTEXTO-PROYECTO.md` (si existe en el entorno de trabajo del equipo).

| Decisión | Valor elegido | Alternativas descartadas | Por qué |
|---|---|---|---|
| Despliegue | Docker Compose local, 100% offline salvo la API del LLM | Cloudflare Workers/D1/KV, Kubernetes | El PRD original traía dos arquitecturas incompatibles conviviendo en el mismo documento; Docker local es reproducible en una laptop en horas de hackathon sin depender de cuotas de un proveedor cloud. |
| Backend | Python 3.11 + FastAPI | Node.js | Permite compartir el mismo lenguaje con el entrenamiento ML (scikit-learn) sin un segundo runtime. |
| Base de datos | PostgreSQL 16 | SQLite / Cloudflare D1 | Soporta los índices compuestos, transacciones y roles/grants que exige la inmutabilidad de `audit_log`; D1 estaba ligado a la arquitectura Cloudflare descartada. |
| Motor de detección | Híbrido: reglas regex deterministas (deciden el bloqueo) + ML ligero (score adicional) | Solo ML puro, solo reglas puras | Un motor 100% ML no puede garantizar <10 ms ni explicabilidad regla→técnica ATT&CK; reglas puras no demuestran el componente de ML que exige el SDD #23. El bloqueo nunca depende del ML para que la demo sea determinista. |
| Capa de inspección | HTTP capa 7 vía gateway inline (reverse proxy) | Captura de flujos de red (PCAP/NetFlow) | El SDD #23 original apunta a flujos de red completos, fuera de alcance en 12 horas; HTTP capa 7 permite demostrar el mismo concepto (detección + IPS + auditoría) contra objetivos propios y controlados. |
| Dataset de entrenamiento ML | NSL-KDD (~25 MB) | Corpus 100% sintético propio | Dataset público, liviano, etiquetado y estándar de la industria para comparar F1/FP; un corpus propio no habría tenido volumen suficiente en el tiempo disponible. |
| Proveedor de IA (triage) | API de DeepSeek (compatible OpenAI), detrás de `LLMProvider` | Cloudflare Workers AI, Anthropic, Gemini | El equipo ya tenía acceso confirmado a la API de DeepSeek; la interfaz `LLMProvider` evita acoplar el código a un único proveedor para el techo post-hackathon. |
| Autoridad de bloqueo | Siempre el motor determinista; el LLM solo redacta | Dar al LLM capacidad de bloquear o ajustar severidad | Mitiga que un ataque de inyección de prompts embebido en el tráfico malicioso se traduzca en una acción real del sistema; es también el argumento central del criterio de "ética y responsabilidad" del jurado. |
| Nivel de vulnerabilidades de laboratorio | 4–6 fallos clásicos de libro de texto (SQLi, LFI, path traversal, command injection), datos sintéticos | CVEs reales, exploits de día cero, alcance MITRE ATT&CK completo | Alcance real para 12 horas; mismo patrón pedagógico que DVWA/Juice Shop/WebGoat. El alcance de "cualquier CVE + ATT&CK completo" del PRD original era irreal en el tiempo disponible. |
| Alcance del Observatorio en Sprint 1 | Vista pública de solo lectura, alimentada automáticamente por el motor | Exportación PDF/CSV, ingesta manual | La tesis de unificación exige que el Observatorio no se llene a mano; exportación queda para Sprint 2+. |
| Inmutabilidad de la auditoría | Cadena de hashes `sha256` encadenada + `REVOKE UPDATE/DELETE` al rol de la app | Confiar solo en backups o en la cadena de hashes sin restricción de permisos | "Registros auditables inmutables" sin mecanismo real era una afirmación no verificable del PRD original; las dos capas juntas hacen que ni un bug del backend pueda alterar una fila ya escrita. |
